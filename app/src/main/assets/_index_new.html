🧩 插件
插件编写格式说明（照着写就能用）

插件是一个 纯文本 JSON 文件，字段如下：

  • id 唯一标识（英文/数字，可省略，会自动生成）
  • name 插件名（必填）
  • version 版本号，如 1.0.0
  • author / desc 作者、说明（可选）
  • prompt 给 AI 的提示词（可选，装了就一直生效）
  • main 插件主代码（JS 字符串，在 App 内直接运行），用下面 api. 接口给 App 加能力
  • scripts 脚本工具数组（可选）：[{ "name":"x", "desc":"…", "lang":"python", "code":"print(1)" }]
main 里可用的 api：
  • api.registerTool({ name, desc, parameters, run: function(args){ return "结果字符串"; } }) —— 给 AI 加一个工具
  • api.registerPrompt("…") —— 加一段给 AI 的提示词
  • api.addButton({ label:"按钮名", tip:"提示", onClick:function(){ } }) —— 工具行加按钮
  • api.toast("…") 弹提示；api.storage.get/set/del(k[,v]) 存数据；api.termux(cmd) 执行终端命令
完整示例（复制即用）： 
{"id":"calc_demo","name":"计算器插件","version":"1.0.0","author":"你的名字","desc":"给 AI 加一个计算器工具","prompt":"需要算术时请调用 calc 工具，不要自己心算。","main":"api.registerTool({name:\"calc\",desc:\"计算数学表达式\",parameters:{type:\"object\",properties:{expr:{type:\"string\",description:\"表达式\"}},required:[\"expr\"]},run:function(a){try{return String(a.expr)+\" = \"+Function(\"return (\"+a.expr+\")\")();}catch(e){return \"算不出来\";}}});"}

注意：main 写在 JSON 字符串里，里面的双引号要写成 \"（转义）。写好 JSON 后点下面「粘贴 JSON 导入」或「从文件导入(.json)」即可安装。

插件是真正装进 App 的代码包：能给 AI 加工具、给界面加按钮、加提示词，像给 App 装扩展一样，导入即启用、可随时停用。

插件里的 JS 代码会在 App 内直接运行（用 api.registerTool 给 AI 加工具、api.addButton 加按钮、api.storage 存数据、api.termux 执行命令）。停用后它的工具与按钮立刻消失。插件包是纯文本 JSON，可分享给他人导入。

🔌 MCP 工具（外部能力扩展）▸ 展开

⚠️ 坦白说：这个功能对你目前基本没用，建议保持关闭。
为什么没用：MCP 的卖点是「不用写代码就能接外部工具」，但你已经有内置终端（termux_exec）——实测 git、sqlite3、curl 都能直连，自己写个脚本比装 MCP 服务更直接。而且这台手机上，pip 装 Python 版 SDK 会因缺少 Rust 编译环境而失败，npm 装 Node 版服务极慢（实测装一个小包要 2 分钟），所以「插上就能用」的生态优势在手机端基本落空。
什么时候才有用：将来若要接带 OAuth 登录的云服务（如 Notion、Slack），且由对方托管好凭证时，它才省事。
建议：保持关闭。留着它只是为了将来留一个「插座」，默认不耗 token、不占资源。

MCP（Model Context Protocol）让 AI 能调用外部工具服务。开启后，App 会在内置 Termux 里运行一个本地网关，并把它提供的工具交给 AI 使用。工具会随对话一起发给模型，数量多时略增 token 消耗。
